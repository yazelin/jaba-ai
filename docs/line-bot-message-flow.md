# LINE Bot 流程說明

## 一、群組開通流程

### 完整流程圖

```

└─────────────────────────────────────────────────────────────────────┘

        ▼

        │
        ▼
```

### 管理員綁定流程

```
1. 成員輸入「管理員 [群組代碼]」
        │
        ▼
2. 系統驗證
   ├─ 群組是否已啟用？(status = "active")
   └─ 代碼是否正確？(group.group_code)
        │
        ├─ 驗證失敗 → 回應「⚠️ 代碼錯誤或群組未啟用」
        │
        └─ 驗證成功
            │
            ▼
3. 建立 GroupAdmin 記錄
   └─ group_id = 群組 ID
   └─ user_id = 使用者 ID
        │
        ▼
4. 回應「✅ 已綁定為管理員」+ 可用指令說明
```

### 重要說明

- **群組代碼用途**：管理員綁定、LINE 管理員後台登入
- **群組代碼設定**：申請時由申請者自訂，開通後可在 LINE 管理員後台變更
- **多群組共用代碼**：同一公司可以多個群組使用相同代碼

## 二、開單點餐流程

### 完整流程圖

```
┌─────────────────────────────────────────────────────────────────────┐
│                      開單點餐完整流程                                 │
└─────────────────────────────────────────────────────────────────────┘

1. 管理員輸入店名（例如「家香味」或「家香味菜單」）
   └─ 設定今日店家並直接開單（跳到步驟 3）
   └─ 輸入「今日」可查看可用店家；「加 [店名]」只加店家不開單
        │
        ▼
2. 或成員輸入「開單」／「請開單」
        │
        ├─ 檢查：今日店家是否已設定？
        │   └─ 否 → 回應「⚠️ 尚未設定今日店家」
        │
        ├─ 檢查：是否已有進行中的點餐？
        │   └─ 是 → 回應「⚠️ 已經在點餐中了」
        │
        └─ 通過
            │
            ▼
3. 建立 OrderSession
   └─ status = "ordering"
   └─ started_by = 發起者 ID
   └─ 記錄系統訊息「=== 新的點餐開始 ===」
        │
        ▼
4. 廣播 session_status 事件
   └─ 前端看板即時更新
        │
        ▼
5. 回應開單成功 + 今日菜單
   └─ 「🍱 開始群組點餐！」
   └─ 顯示店家菜單
   └─ 「直接說出餐點即可，說「收單」結束」
        │
        ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        點餐進行中                                    │
└─────────────────────────────────────────────────────────────────────┘
        │
        ▼
6. 成員發送點餐訊息
   └─ 例如：「炸排骨+1」「銷魂飯*2(老闆)」「我想吃最辣的」
        │
        ├─ 規則解析看得懂（約八成）→ 程式直接寫入，回本人確認行
        │   「同事A：古早味排骨（便當）×1，小計 $110」，跳到步驟 12
        │
        ▼ 看不懂才走 AI
7. 訊息前處理
   ├─ sanitize_user_input() 過濾惡意內容
   └─ 記錄 ChatMessage (role = "user")
        │
        ▼
8. 組建 AI Context（詳見架構文檔）
   ├─ mode: "group_ordering"
   ├─ user_name: 發言者名稱
   ├─ today_stores: 今日店家列表
   ├─ menus: 完整菜單（含價格、變體）
   ├─ session_orders: 本次所有人的訂單
   └─ user_preferences: 發言者偏好設定
        │
        ▼
9. 呼叫 Claude Code CLI
   └─ 傳入 system_prompt (group_ordering)
   └─ 傳入 context + history + 當前訊息
        │
        ▼
10. AI 回應 JSON
    {
      "message": "好～幫你點一個雞腿便當 $85！",
      "actions": [
        {
          "type": "group_create_order",
          "data": {
            "items": [{"name": "雞腿便當", "quantity": 1, "note": ""}]
          }
        }
      ]
    }
        │
        ▼
11. 驗證並執行 Actions（見「AI 路徑的安全規則」）
    ├─ group_create_order → 品項重新對菜單後寫入
    ├─ group_set_order    → 整份取代本人訂單
    ├─ group_update_order → 修改訂單品項
    ├─ group_remove_item  → 移除品項
    └─ group_cancel_order → 使用者明講取消才執行
        │
        ▼
12. 資料庫 Commit + 廣播 order_update 事件
    └─ 前端看板即時更新訂單列表
        │
        ▼
13. 記錄 AI 回應 (ChatMessage role = "assistant")
        │
        ▼
14. 回覆：訂單有變動 → 資料庫產生的確認行；沒變動 → AI 的 message
        │
        ▼
    （重複步驟 6-14 直到收單）
        │
        ▼
┌─────────────────────────────────────────────────────────────────────┐
│                          收單結算                                    │
└─────────────────────────────────────────────────────────────────────┘
        │
        ▼
15. 成員輸入「收單」或「結單」
        │
        ▼
16. 結束 OrderSession
    └─ status = "ended"
    └─ ended_by = 收單者 ID
    └─ ended_at = 當前時間
        │
        ▼
17. 產生訂單摘要
    ├─ 每人點餐明細 + 金額（已付款的標示「已付」）
    ├─ 品項統計（雞腿便當 x3、排骨飯 x2...）
    ├─ 總金額
    ├─ 各店菜單價格最後更新日期（超過三個月會提醒）
    └─ 收款提示：管理員打「已付 名字」標記、「收款」看誰還沒付
        │
        ▼
18. 廣播 session_status 事件 (status = "ended")
        │
        ▼
19. 回應收單成功 + 訂單摘要
```

### AI Action Types

| Action Type | 說明 | data 結構 |
|------------|------|----------|
| `group_create_order` | 建立訂單品項 | `{items: [{name, quantity, note, category}]}` |
| `group_set_order` | 整份取代本人訂單 | `{items: [{name, quantity, note, category}]}` |
| `group_update_order` | 修改訂單品項 | `{old_item: "原品項", new_item: {name, quantity}}` |
| `group_remove_item` | 移除特定品項 | `{item_name: "品項名稱", quantity}` |
| `group_cancel_order` | 取消整筆訂單（使用者明講取消才執行） | `{}` |

## 三、訊息處理流程

### 處理順序

```
群組訊息進入
│
├─0. 正規化：去掉 @呷爸 提及、全形轉半形
│    取得群組鎖（同一群組一次處理一則，同時點餐不會互相覆蓋）
│
├─1. 特殊指令（help、呷爸、?、id）
│
├─2. 群組未啟用 → 引導申請並結束
│
├─3. 新增成員記錄
│
├─4. 進行中的單不是今天開的 → 自動結單
│
├─5. 快捷指令（開單／請開單、收單／結單、菜單、目前訂單）
│
├─6. 點餐中 → 規則解析（order_parser.py）
│   └─ 看得懂 → 程式直接寫入訂單，回本人確認行，結束
│
├─7. 管理員指令（點餐中也生效）
│   ├─「管理員 [代碼]」「管理員1234」→ 綁定（任何人可嘗試）
│   ├─ 非管理員打「XX菜單」→ 顯示今日菜單
│   └─ 管理員：今日、清除、改價、已付、收款、加、移除、
│      店名／XX菜單 → 設定店家並開單
│
├─8. 明顯不是點餐（@ 其他人、網址、超過 60 字）→ 不回、不問 AI
│
├─9. 沒開單
│   ├─ 帶數量的點餐（「炸排骨+1」）＋ 今日店家已設定 → 自動開單並寫入
│   ├─ 帶數量的點餐 ＋ 還沒設定店家 → 暫存，同一天提醒一次，開單時補上
│   └─ 其他 → 不回應
│
└─10. 點餐中、規則看不懂 → AI 解析意圖 → 程式驗證後寫入
```

### 規則解析看得懂的寫法

| 寫法 | 範例 | 結果 |
|---|---|---|
| 品項、品項＋數量 | `炸排骨`、`炸排骨+1`、`銷魂飯*5`、`古早味排骨 x4` | 加入 |
| 帶價格 | `鹹豬肉 $105 +1` | 價格以菜單為準 |
| 代訂 | `銷魂飯(小李)*1`、`椒鹽雞塊*3 (老闆)`、`小李:銷魂飯` | 加在發訊息者名下，備註代訂對象 |
| 多品項 | 換行、空白、`黯然飯*3+銷魂飯*1` | 逐項加入 |
| 減少 | `少一個蔥油雞`、`炸排骨少3個`、`-2` | 減少本人的品項 |
| 取消 | `取消`、`我不要炸雞腿飯了` | 刪除本人整筆或該品項 |
| 改 | `改炸雞腿`、`蔥油雞*3改蔥爆豬*3` | 刪舊加新 |
| 跟單 | `+1`、`我也要` | 複製最近一位的品項 |
| 選項 | `麵`、`單點` | 把本人最後一項換成麵或單點 |
| 追加 | `再加一個黯然飯`、`追加3個椒鹽雞塊飯` | 一定追加 |

- 沒講飯或麵就照飯，沒講便當或單點就照便當，不追問；確認行會註明
- 同一品項對到多個菜單項目時，回編號讓使用者選
- 和本人原本的訂單完全一樣的訊息（重傳、重貼整份）不重複加，確認行會提醒「要多一份請打再加一個」

### AI 路徑的安全規則

- AI 回傳的品項名稱一律重新對菜單，對不到就不寫入
- 使用者沒說取消、不要、算了，就不執行「取消整筆」
- 同一則同時「取消整筆」和「新增」，視為整份重設
- 訂單有變動時，回覆一律是資料庫產生的確認行，不用 AI 寫的文字
- AI 呼叫失敗（逾時、登入過期）回「AI 暫時連不上，固定格式的點餐還是可以用」，原始錯誤只記 log

## 四、指令列表

### 快捷指令（所有人可用）

| 指令 | 說明 |
|-----|------|
| `開單` / `請開單` | 開始群組點餐（要先設定今日店家） |
| `收單` / `結單` | 結束點餐，貼出摘要 |
| `菜單` / `XX菜單` | 顯示今日菜單 |
| `目前訂單` / `訂單` / `統計` | 顯示目前訂單摘要 |

### 管理員指令（點餐中也可用）

| 指令 | 說明 |
|-----|------|
| `管理員 [群組代碼]` | 綁定管理員身份 |
| `解除管理員` | 解除管理員身份（非唯一管理員） |
| `[店名]` / `[店名]菜單` | 設定今日店家並開單；已經有人點了別家，會請你先結單。結尾是「菜單」「開單」時，店名錯一個字也認得，對不到就列出可用店家 |
| `今日` | 查看今日店家 + 可用店家列表 |
| `加 [店名]` / `移除 [店名]` / `清除` | 調整今日店家 |
| `改價 [品項] [金額]` | 改菜單價格，今天還開著的單一起改 |
| `已付 [名字]` | 標記這次點餐某人已付款 |
| `收款` | 列出還沒付的人與金額 |

### 特殊指令

| 指令 | 說明 |
|-----|------|
| `help` / `呷爸` / `@呷爸` / `幫助` / `?` | 顯示幫助訊息 |
| `id` / `群組id` | 顯示群組 ID 和使用者 ID |

## 五、關鍵規則

1. **訂單只由程式寫入** - 規則解析或 AI 解析的結果，都經過程式驗證才寫入；回覆內容取自資料庫
2. **開單前的點餐不丟** - 店家已設定就自動開單，沒設定就暫存到開單時補上
3. **舊單自動關** - 收到訊息時發現單不是今天開的就結束；每天 15:00（`AUTO_CLOSE_HOUR`）再結一次，空單刪除
4. **管理員指令點餐中也有效** - 但已經有人點了，不會自動換店
5. **群組裡少說話** - 每次點餐只回本人一行，完整清單只在「目前訂單」與結單時出現
